# Research Datasets and Benchmarks for an AI DJ-Transition Pipeline (House Music), as of 2026-10-07

Scope note: "Live as of 2026-10-07" claims below come from HTTP status checks run from this research environment on that date (HEAD/GET through a proxy). GitHub URLs returned HTTP 403 through this proxy for *every* repository, so a GitHub 403 here is NOT evidence that a repo is dead; where a GitHub repo is listed as alive it is because its README was successfully rendered during this research. All other liveness claims are direct observations.

## Key Question 1: Tempo and key ground truth on EDM (GiantSteps, GiantSteps-MTG/Beatport key, Schreiber corrections, essentia edma accuracy)

### Takeaway
The two original GiantSteps datasets (tempo: 664 clips, key: 604 clips) distribute only annotations; their Beatport preview-audio download links (geo-samples.beatport.com/lofi/*.LOFI.mp3) returned HTTP 404 on 2026-10-07, so the audio is effectively dead unless you already hold a copy. Faraldo's two Zenodo revisions (GiantSteps+ EDM Key, 600 clips, and Beatport EDM Key Dataset, 1,486 clips) ship the audio inside the record under CC BY-SA 4.0 and are live, making them the practical key ground truth for EDM; no equivalent audio-bearing redistribution of the GiantSteps *tempo* set was found.

### Cited Findings
- GiantSteps Tempo: 664 Beatport audio previews, mostly 120 s (six exceptions, e.g. 906760 at 62 s, 1327052 at 70 s), ~1 GB mp3, fetched by `./audio_dl.sh` from `http://geo-samples.beatport.com/lofi/<id>.LOFI.mp3`; `annotations/` = Knees et al. ISMIR 2015 tempo from Beatport forum user corrections (tempo, genre, GiantSteps and JAMS formats); `annotations_v2/` = Schreiber & Müller ISMIR 2018 crowdsourced tempo (tempo, JAMS, MIREX-style T1 T2 ST1 files); three files (3041381, 3041383, 1327052) have no v2 tempo. The README states no licence — [GiantSteps tempo GitHub](https://github.com/GiantSteps/giantsteps-tempo-dataset)
- mirdata's loader records the licence as CC BY-SA 4.0 and says the audio "is not available for download" via mirdata; it must be fetched from Beatport using the repo script; annotation snapshot zip URL is `https://github.com/GiantSteps/giantsteps-tempo-dataset/archive/0b7d47ba8cae59d3535a02e3db69e2cf6d0af5bb.zip` — [mirdata giantsteps_tempo loader](https://mirdata.readthedocs.io/en/stable/_modules/mirdata/datasets/giantsteps_tempo.html)
- Liveness check 2026-10-07: `http://geo-samples.beatport.com/lofi/5377710.LOFI.mp3` (the README's own example) and `https://geo-samples.beatport.com/lofi/1327052.LOFI.mp3` both returned HTTP 404 (also 404 over https for 5377710). The GiantSteps tempo and key audio download scripts are therefore dead as of this date — direct HTTP check from this environment (no external page to cite; the URL pattern is documented in the [GiantSteps tempo README](https://github.com/GiantSteps/giantsteps-tempo-dataset))
- GiantSteps Key: 604 2-min Beatport previews (~850 MB; four shorter clips, e.g. 1224698 at 45 s), same `geo-samples.beatport.com/lofi/` download pattern (so same dead links), key labels "extracted from forum entries of people correcting the key annotations", genre parsed from Beatport JSON; annotations in `annotations/key/`, `annotations/giantsteps/`, `annotations/jams/`; no licence stated in README — [GiantSteps key GitHub](https://github.com/GiantSteps/giantsteps-key-dataset)
- GiantSteps+ EDM Key Dataset (Zenodo 10.5281/zenodo.1095691): Faraldo's revision of the GiantSteps Key set; 600 two-minute excerpts from various EDM subgenres, with `audio.zip` (855.8 MB) INCLUDED in the record plus `keys.zip`, `original_metadata.zip`, `GiantSteps+.xlsx`; 500 tracks additionally analysed with pitch-class sets, key changes and modal changes; single-key labels + comments + confidence levels (original labels by Daniel G. Camhi); CC BY-SA 4.0; a newer version of the record exists — [Zenodo 1095691](https://zenodo.org/record/1095691); Zenodo API returned HTTP 200 on 2026-10-07
- Beatport EDM Key Dataset (Zenodo 10.5281/zenodo.1101082, Dec 21 2017): 1,486 two-minute Beatport excerpts, `audio.zip` 2.1 GB INCLUDED, `keys.zip` 380 kB, `original_metadata.zip` 921 kB, xlsx 148 kB; single-key label + comments + confidence per excerpt; Ángel Faraldo (creator), Eduard Mas Marín (original annotations); CC BY-SA 4.0; open access; 4,919 downloads — [Zenodo 1101082](https://zenodo.org/record/1101082); Zenodo API HTTP 200 on 2026-10-07
- The "GiantSteps-MTG Key" set used in the key-estimation literature is this 1,486-excerpt Beatport set; Korzeniowski & Widmer used only the 1,077 excerpts with a single key and high confidence for training, and the 604-track GiantSteps Key set for testing — [Korzeniowski & Widmer 2017, arXiv 1706.02921](https://arxiv.org/pdf/1706.02921)
- Key accuracy on GiantSteps Key (604 tracks), weighted MIREX score / % exactly correct: CNN trained on GSMTG 74.3 / 67.9; EDMM (Faraldo et al. profile) 70.1 / 63.7; EDMA (Faraldo et al. profile) 65.6 / 57.8 (65.5 in the paper's text); QM Key Detector 50.4 / 39.6; EDMT 44.6 / 33.6; CNN trained on Billboard only 57.3 / 47.0. The authors note their EDM-profile numbers differ from Faraldo's originals because of a stricter "fifth" criterion and library changes — [Korzeniowski & Widmer 2017](https://arxiv.org/pdf/1706.02921)
- Essentia's Key algorithm reference page (which exposes the `edma`/`edmm` profile types used above) — [essentia std_Key reference](https://essentia.upf.edu/reference/std_Key.html); Faraldo's "A multi-profile method for key estimation in EDM" is at the UPF repository but returned an access-denied page during this research — [UPF repositori](https://repositori.upf.edu/items/cbc3155d-661b-46fd-9120-7054f57cbbfb/full)
- The Beat This! Zenodo release (see KQ2) includes pitch-shifted (-5..+6 semitones) and time-stretched (-20%..+20%) spectrogram augmentations for its training sets, which is relevant to tempo-robust training — [Zenodo 13922116](https://zenodo.org/records/13922116)

### Inferences
- For key ground truth on house/tech-house, use Zenodo 1101082 (1,486 clips, audio included) for training and Zenodo 1095691 (600 clips, audio included, overlaps the original GiantSteps Key 604) for evaluation; this reproduces the standard GS/GSMTG split without touching Beatport.
- For tempo ground truth on EDM there is currently no audio-bearing redistribution of GiantSteps Tempo; the 664 annotation files are only useful if you can recover audio by Beatport track ID through another route (the ID is encoded in the filename). Raveform (KQ4) is the only live EDM corpus found with manually corrected tempo/beat grids (1,423 tracks), albeit with YouTube-ID audio.
- "Good" key accuracy on EDM is roughly 58-64% exact / 66-70 weighted for template methods (edma/edmm) and ~68% exact / 74 weighted for a 2017 CNN; a system that matches or beats edmm on the Beatport sets is at state-of-the-art-template level.

### Gaps
- No published accuracy of Mixed In Key or KeyFinder on GiantSteps/Beatport sets was found in the sources retrieved.
- Per-genre breakdown (deep/melodic/tech house counts) of the Beatport key sets was not in the Zenodo page text; it is inside the xlsx/original_metadata zips.
- Could not confirm whether any mirror of the GiantSteps *tempo* audio exists (the Zenodo key records do not include the 664 tempo clips as such; overlap between the key and tempo track IDs was not checked).
- Freesound Loop Dataset (arXiv 2008.11507) surfaced as a lead for tempo/key-annotated CC loops but was not examined.

## Key Question 2: Beat/downbeat ground truth and groove data (Ballroom, Hainsworth, SMC, GTZAN, Harmonix, HJDB, Groove MIDI, Beat This! sets)

### Takeaway
The single most practical source is the Beat This! Zenodo release (CC BY 4.0, 141 GB), which bundles preprocessed mel-spectrograms plus beat/downbeat annotations for 16 datasets including Harmonix and HJDB, side-stepping dead audio; Harmonix itself (912 tracks) is distributed as annotations + Dropbox mel-spectrograms + a YouTube URL list, and Groove MIDI (13.6 h, CC BY 4.0) gives drummer micro-timing but has no house/electronic style, only "dance".

### Cited Findings
- Beat This! (Foscarin, Schlüter, Widmer, ISMIR 2024) trained on 18 datasets totalling 4,556 tracks: Simac, SMC, Hainsworth, Ballroom, HJDB, Beatles, Harmonix, RWC (classical, pop, royalty-free, jazz), TapCorrect, JAAH, Filosax, ASAP, Groove MIDI, GuitarSet, Candombe; GTZAN (993 pieces) used as test only — [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- Beat This! 8-fold CV F1 (beat / downbeat, %): Ballroom 97.5 / 95.3; Hainsworth 91.9 / 80.0; SMC 62.7 / –; Harmonix 95.8 / 90.7; HJDB 98.2 / 96.6; GTZAN (held-out test) 89.1±0.3 / 78.3±0.4; baseline Hung et al. (ICASSP 2022 transformer): Ballroom 96.2/93.7, Hainsworth 87.7/74.8, SMC 60.5, Harmonix 95.3/90.8, GTZAN 88.7/75.6 — [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- Beat This! states beat tracking "is not a solved problem, even for commonly targeted genres such as rock or electronic music, especially for the downbeat tracking task"; code and models at github.com/CPJKU/beat_this (no licence stated in the paper) — [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- "Beat This! Spectrograms for Beat and Downbeat Tracking" (Zenodo 10.5281/zenodo.13922116, Oct 14 2024, Schlüter & Foscarin, JKU): preprocessed mel-spectrograms + beat/downbeat annotations for 16 datasets (asap, ballroom, beatles, candombe, filosax, groove_midi, gtzan, guitarset, hainsworth, harmonix, hjdb, jaah, rwc, simac, smc, tapcorrect); 22,050 Hz, 1024 window, 441 hop (50 fps), 128 mel bands 30 Hz-11 kHz, ln(1+1000x), float16; each track with 11 pitch-shifted (-5..+6 st) and 10 time-stretched (-20..+20%) variants (GTZAN original only); ~141.2 GB total, harmonix.zip 45.1 GB; CC BY 4.0; Harmonix annotations are the Hung et al. 2022 version; newer annotations at GitHub CPJKU/beat_this_annotations — [Zenodo 13922116](https://zenodo.org/records/13922116); HTTP 200 on 2026-10-07
- Harmonix Set (Nieto et al., ISMIR 2019): beats, downbeats (beat position in bar + bar number) and functional segment boundaries/labels for 912 tracks, JAMS 0.3.3 files; mel-spectrograms for the full set on Dropbox (~1.2 GB, updated Dec 2020, users must agree to an included licence); `youtube_urls.csv` maps each track to a YouTube video and `youtube_alignment_scores.csv` gives DTW alignment scores of YouTube audio vs. the original annotated audio; repo MIT; the README describes the music as Western Pop and does not state whether the YouTube links still work — [urinieto/harmonixset](https://github.com/urinieto/harmonixset); paper — [ISMIR 2019](https://ir.webis.de/anthology/2019.ismir_conference-2019.68)
- madmom's DBN downbeat tracker (Böck, Krebs, Widmer, ISMIR 2016 "Joint Beat and Downbeat Tracking with RNNs"), bar lengths 3 and 4, F1 beat / downbeat: Ballroom (5 h 57 m) 0.938 / 0.863; Hainsworth (222 files, 3 h 19 m) 0.867 / 0.684; Beatles (180 files, 8 h 09 m) 0.918 / 0.832; RWC Popular (100 files, 6 h 47 m) 0.943 / 0.861; Klapuri (test only) 0.811 / 0.745; Carnatic 0.804 / 0.365; HJDB (235 files, 3 h 19 m), Rock (200 files) and Robbie Williams (65 files) were in the training list without reported scores — [ISMIR 2016 paper](https://archives.ismir.net/ismir2016/paper/000186.pdf); madmom API — [DBNDownBeatTrackingProcessor docs](https://madmom.readthedocs.io/en/v0.16/modules/features/downbeats.html)
- HJDB is a hardcore / jungle / drum-and-bass set and is the dataset on which Beat This! scores highest (98.2 / 96.6) — [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- Groove MIDI Dataset (Magenta/Google): 13.6 h, 1,150 MIDI files, >22,000 measures, 10 drummers (>80% of duration from hired professionals), MIDI aligned to synthesized/recorded audio within 2 ms; metadata per performance: drummer ID, session, style (primary/secondary), integer BPM (played to click), beat vs. fill, time signature, split; hi-hat pedal as CC4; styles: afrobeat, afrocuban, blues, country, dance, funk, gospel, highlife, hiphop, jazz, latin, middleeastern, neworleans, pop, punk, reggae, rock, soul (no house/electronic); CC BY 4.0; full zip (MIDI+WAV+CSV) 4.76 GB at storage.googleapis.com/magentadata/datasets/groove/groove-v1.0.0.zip; MIDI-only 3.11 MB; E-GMD extension for drum transcription — [Magenta Groove page](https://magenta.tensorflow.org/datasets/groove); HTTP 200 on 2026-10-07
- Raveform (KQ4) provides estimated beats/downbeats for all 4,902 mixes and 56,873 tracks and manually corrected beats, downbeats and tempo for 1,423 EDM tracks — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- EDM-CUE (KQ4) carries a `beat_grid` (bpm, init_beat, start_pos, time_sig) for ~4,710 EDM tracks (Deezer IDs only) — [HF disco-eth/edm-cue README](https://huggingface.co/datasets/disco-eth/edm-cue/blob/main/README.md)

### Inferences
- For a house pipeline, HJDB (fast breakbeat) and Harmonix (pop with some dance) are the closest classic beat sets; the Beat This! Zenodo bundle is the cheapest route to both, but it delivers fixed 50 fps mel-spectrograms, not waveforms, so it cannot validate a pipeline stage that operates on raw audio or at a different frontend.
- Groove MIDI is useful for groove/micro-timing modelling of acoustic-kit playing, not for 4/4 quantised house drum programming; its "dance" style subset would need checking for size.
- Reference accuracy for "good" beat tracking in 2024-25: ~96-98% beat F1 and ~90-97% downbeat F1 on dance-adjacent sets (Harmonix, HJDB); madmom (2016) sits at ~0.86-0.94 beat / 0.68-0.86 downbeat on the classic sets.

### Gaps
- Harmonix YouTube link liveness could not be checked (no YouTube access from this environment); the repo's own alignment-score file implies some YouTube versions already differ from the annotated audio.
- The exact Harmonix genre distribution (how many EDM tracks) was not in the README text; it is in `metadata.tsv`.
- Ballroom file count was ambiguous in the extracted Böck 2016 table ("2,685" is almost certainly a parsing artefact for 685 unique files); treat the hours (5 h 57 m) as reliable and verify the count against the paper.
- ENST-Drums: the historical IRCAM URL (anasynth.ircam.fr/home/media/ENST-drums) returned 404 on 2026-10-07; a current host was not located.
- No 2025-2026 EDM-specific beat/downbeat dataset beyond Raveform was found.

## Key Question 3: Structure / section boundaries (SALAMI, Harmonix, Isophonics, EDM drop/breakdown sets)

### Takeaway
Raveform (2026) is the only live, EDM-specific structure dataset found: 1,423 tracks hand-labelled with an EDM vocabulary (Intro, Buildup, Breakdown, Drop, Cooldown, Bridge, Outro, Ambient-intro/outro) alongside beats/downbeats; SALAMI (CC0 annotations, no audio) and Harmonix (912 pop tracks) remain the general-purpose sets, and the 2014 Yadati drop-detection corpus (100 SoundCloud tracks) was never clearly released.

### Cited Findings
- Raveform structural annotations: 1,423 EDM tracks with manually annotated functional segment boundaries and labels from the vocabulary Intro, Buildup, Breakdown, Drop, Cooldown, Bridge, Outro, Ambient-intro, Ambient-outro, plus corrected beats/downbeats and tempo; annotated-track genres (Beatport tags): Techno (~550), then Trance, Drum & Bass, Tech House, Mainstage, Deep House, House; tempo peaks at 128 BPM with a 170-175 BPM DnB cluster — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- Raveform files: `structures/beats/<TRACK_KEY>.beat.csv` (beats, downbeats, section labels) and `structures/segments.json` (tempo + segment boundaries/labels, with 8-fold CV folds for the All-In-One model); download `https://huggingface.co/datasets/taejunkim/raveform/resolve/main/raveform.zip`; code github.com/mir-aidj/raveform; no licence stated on the project page — [Raveform project page](https://mir-aidj.github.io/raveform/); HF zip returned HTTP 200 on 2026-10-07
- Raveform benchmarks: All-In-One (Kim & Nam 2023) trained on Raveform, Harmonix or both, compared with madmom; models trained on Raveform scored higher on Raveform than Harmonix-trained models did on Harmonix, which the authors attribute to more consistent EDM annotations — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- Harmonix Set: functional segment boundaries + labels for 912 tracks (segments directory and JAMS), MIT repo, spectrograms + YouTube URL list (see KQ2) — [urinieto/harmonixset](https://github.com/urinieto/harmonixset)
- SALAMI (McGill DDMAL): annotation data dedicated to the public domain (CC0); the public release "contains about half of the total data we collected"; no audio distributed, but a script downloads Internet-Archive-hosted audio and Echo Nest-derived beat/bar/section/tempo/key features are included; latest data on their GitHub; cite Smith et al. ISMIR 2011 — [SALAMI annotation page](https://ddmal.music.mcgill.ca/research/salami/annotation); ISMIR 2011 paper — [archives.ismir.net](https://archives.ismir.net/ismir2011/paper/000099.pdf)
- Yadati, Larson, Liem, Hanjalic (ISMIR 2014) "Detecting Drops in EDM": 100 SoundCloud tracks (dubstep 36, electro 36, house 28), 60/20/20 split; drops located via SoundCloud timed comments containing "drop" (225 comments → 190 drops), then one author manually labelled the drop point ("where the buildup ends and the bassline is re-introduced", ~6 h of labelling); content-based F1 0.61 at 3 s tolerance → 0.71 at 15 s; the paper does not say the audio or annotations were released — [ISMIR 2014 PDF](https://archives.ismir.net/ismir2014/paper/000297.pdf); Zenodo record 1417081 is only the paper PDF (CC BY 4.0), not a dataset — [Zenodo 1417081](https://zenodo.org/records/1417081)
- MediaEval 2014 ran a drop-detection task on EDM (working notes exist) — [MediaEval 2014 working note](https://ceur-ws.org/Vol-1263/mediaeval2014_submission_88.pdf)
- EDM-CUE cue points (21k over ~4.7k tracks) "show high adherence to phrasing" per the paper and can be read as phrase/section-boundary ground truth — [arXiv 2407.06823](https://arxiv.org/abs/2407.06823)

### Inferences
- A house transition system needs breakdown/drop boundaries far more than SALAMI's verse/chorus labels; Raveform's 1,423 tracks (with Tech House and Deep House present but Techno-dominated) are the realistic validation set, and EDM-CUE's 21k cue points can serve as a second, phrase-level signal.
- Yadati's corpus should be treated as unavailable; re-creating it from SoundCloud comments is possible in principle but the 2014 tracks may be gone.

### Gaps
- SALAMI recording count (commonly 1,359) and genre breakdown were not confirmed from the page retrieved; the DDMAL GitHub repo could not be reached through this proxy (403) and salami.music.mcgill.ca failed to connect.
- Isophonics (Beatles/Queen/Zweieck structure annotations) was not examined in this research round.
- No dataset named "BUD" or any other EDM breakdown/drop dataset beyond Raveform and Yadati was found.
- Raveform's quantitative structure F-measures were not extracted from the article text.

## Key Question 4: DJ-mix datasets (UnmixDB, Sonnleitner mixotic set, Kim 2020, Chen 2022, Raveform, EDM-CUE, MixesDB-derived)

### Takeaway
Three DJ-mix resources are live and downloadable in 2026: UnmixDB (Zenodo, 4.2 GB, synthetic mixes with exact cue/tempo ground truth, CC BY-NC-ND 4.0), the Sonnleitner 2016 mixotic set (10 real CC techno/house mixes, 11 h, with track-border annotations, at cp.jku.at), and Raveform (4,902 real mixes / 6,522 h with estimated mix-to-track alignments, audio via YouTube/SoundCloud/Mixcloud links only). Kim et al. 2020's 1001Tracklists corpus and Chen et al. 2022's livetracklist corpus were never released; the ETH EDM-CUE set (21k human cue points, Deezer IDs, MIT) is live.

### Cited Findings
- UnmixDB (Schwarz & Fourer, IRCAM; Zenodo 10.5281/zenodo.1422385, v1 Sept 2018, last modified Aug 2 2024): automatically generated DJ mixes from CC-licensed electronic dance tracks (the Sonnleitner 2016 mixotic tracks); each three-track playlist mixed 12 times (4 effect variants × 3 time-scaling variants); six set archives (044, 123, 222, 230, 275, 281; 85 MB-1.1 GB each), ~4.2 GB total; ground truth as tab-separated label files, cue-region and tempo `.txt` tables (track start/end/cue points per mix, BPM, speed factors) and `.beat.xml` beat files; beat-aligned linear cross-fades; CC BY-NC-ND 4.0; open access, 1,941 downloads; generation code at GitHub Ircam-RnD/unmixdb-creation; EU ABC_DJ project — [Zenodo 1422385](https://zenodo.org/record/1422385); HTTP 200 on 2026-10-07; paper — [HAL hal-02010431](https://hal.archives-ouvertes.fr/hal-02010431); follow-up methods/datasets paper — [HAL hal-03184436](https://hal-univ-evry.archives-ouvertes.fr/hal-03184436)
- Raveform describes UnmixDB's mixes as "automatically generated, which limits their use for studying human DJ behavior" — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- Sonnleitner, Arzt, Widmer (ISMIR 2016) mixotic set: 10 DJ mixes (~11 h 23 m) from the mixotic netlabel, 723 reference tracks of which 118 are played; genres Techno, Chicago House, Deep-Tech, Dub-Techno, Tech-House; song-border annotations marking where the previous track has fully faded out (authors note borders are approximate because of long fades); a second "disco" set (8 mixes, 7 h 16 m, 296 tracks, recorded from club mixing desks) withheld for copyright — [ISMIR 2016 PDF](https://bpb-us-e1.wpmucdn.com/wp.nyu.edu/dist/2/2294/files/2016/07/187_Paper.pdf)
- Download page for the mixotic set: DJ mixes ~1 GB, ground-truth annotations ~6 KB, reference songs ~9.4 GB (with attribution list), 10 mixes / 723 tracks, Creative Commons (URL indicates CC BY-NC-ND 3.0); links point to Google Drive and mixotic.net; page last edited April 3, 2017 — [cp.jku.at fingerprinting datasets](https://www.cp.jku.at/datasets/fingerprinting/); page returned HTTP 200 on 2026-10-07 (individual Google Drive links not tested)
- Kim, Choi, Nam (ISMIR 2020) "A Computational Analysis of Real-World DJ Mixes using Mix-To-Track Subsequence Alignment": 1,557 mixes (1,564 before filtering), 13,728 unique tracks (15,068 before), 24,202 played-track instances, 20,765 transitions; metadata from 1001Tracklists by direct arrangement, audio downloaded from linked media; dataset NOT released (readers told to contact 1001Tracklists), code at GitHub mir-aidj/djmix-analysis, stats site mir-aidj.github.io/djmix-analysis; subsequence DTW on beat-synchronous CENS chroma + 12 MFCCs with key-invariant 12-shift variant; match rate = share of diagonal moves, threshold 0.4; cue-out = last beat followed by 32 diagonal beats, cue-in = first beat preceded by 32; transition-length histogram peaks every 32 beats; DJ cue-point agreement: 23.6% identical, 40.4% within 4 beats, 86.2% within 16 measures; tempo adjustment 86.1% < 5%, 94.5% < 10%, 98.6% < 20%, mean ~127 BPM; only 2.5% of played tracks key-transposed, 94.3% of those by one semitone; mostly House and Trance, poor on Techno — [ar5iv 2008.10267](https://ar5iv.arxiv.org/html/2008.10267)
- Raveform (Kim, Kim, Kim, Nam; TISMIR vol. 9 no. 1 pp. 131-143, published Apr 20 2026, DOI 10.5334/tismir.288): 4,902 DJ mixes, 56,873 unique tracks, 73,505 played-track instances, 1,423 tracks with structure annotations, 6,522 h total mix length, 53,780 available transitions (both tracks identified and audio overlapping after alignment); all non-annotation data from MixesDB (user-contributed; authors warn of inaccuracies, e.g. wrong version listed); only 342 mixes (7%) fully identified; mix-to-track beat-level alignments via Kim et al. 2020 with mix-in/mix-out estimates, pairs with match rate < 0.1 discarded; "mix points" (four per transition) rather than cue points; all-mix genres led by Techno (~1,000 mixes), then House, Tech House, Drum & Bass, Progressive House, Trance; article CC BY 4.0, no separate dataset licence stated — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- Raveform distribution: HF zip (`taejunkim/raveform`), GitHub mir-aidj/raveform; files `mixes.jsonl` (MixesDB metadata + tracklists), `tracks.jsonl`, `mixesdb_genres.jsonl`, `beats/mixes/*.beat.json`, `beats/tracks/*.beat.json`, `alignments/<MIX_ID>.align.jsonl` (mix-in/mix-out + DTW paths), structure files; audio NOT included — tracks are YouTube video IDs, mixes have `audio_url` to SoundCloud / Mixcloud / YouTube / html_audio; ~38% of mixes have timestamps; example mix 23 tracks, 20 identified — [Raveform project page](https://mir-aidj.github.io/raveform/); HF API and zip HTTP 200 on 2026-10-07
- Chen, Hsu, Liao, Martínez Ramírez, Mitsufuji, Yang (Academia Sinica / Sony; ICASSP 2022) "Automatic DJ Transitions with Differentiable Audio Effects and GANs": crawled livetracklist, 284 mixes tagged "mix" split into 7,064 sections each containing one transition (sections < 1 min dropped); paired training tracks generated from MTG-Jamendo tracks tagged "electronic" (1,000 train / 100 test → 8,318 / 830 pairs); listening test 136 retained of 188 participants (α = 0.799), Human rated highest, GAN not significantly different from Linear/Rule baselines; examples and source code at paulyuchen.com/djtransgan-icassp2022, datasets not stated as released — [arXiv 2110.06525](https://arxiv.org/abs/2110.06525)
- EDM-CUE (ETH DISCO; Argüello, Lanzendörfer, Wattenhofer, "Cue Point Estimation using Object Detection", arXiv 2407.06823, July 2024): ~21k manually placed cue points + metronome info for nearly 5k EDM tracks, described as 35× larger than the previous cue-point dataset; HF record counts 4,609 train + 101 validation (4,710); fields: Deezer track `id`, title, artists, duration, genre list ("possibly incomplete"), key (rekordbox-generated, "possibly incorrect"), `beat_grid` (bpm, init_beat, start_pos, time_sig), `cue_pts` (seconds); Parquet, 293 kB download; MIT licence; NO audio and no Beatport/Spotify/YouTube IDs; load via `load_dataset("disco-eth/edm-cue")` — [HF README](https://huggingface.co/datasets/disco-eth/edm-cue/blob/main/README.md); paper — [arXiv 2407.06823](https://arxiv.org/abs/2407.06823); HF API HTTP 200 on 2026-10-07
- Raveform's own summary of related work: Sonnleitner 2016 = 10 mixes / 118 tracks, one version public; Kim 2020 ≈ 1.5k mixes / 15k tracks, not public, no structure; Argüello 2024 = 4,710 tracks / 21k cue points from four professional DJs — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- MixesDB is also exposed to consumer tooling (e.g. a Roon community thread on MixesDB metadata), confirming it is a general-purpose tracklist wiki rather than a research release — [Roon community](https://community.roonlabs.com/t/metadata-support-for-dj-mixes-from-mixesdb-com-disk-jockey/310504)

### Inferences
- Pipeline mapping: UnmixDB validates alignment, tempo-change and cue-point recovery with exact synthetic truth (but only linear cross-fades, no EQ/filter sweeps); the mixotic set validates fingerprint-based track identification and approximate transition boundaries in real techno/house mixes; Raveform validates mix-in/mix-out and transition-length statistics at scale but its alignments are themselves estimates (not hand truth) and its audio must be re-fetched from YouTube/SoundCloud with the usual rot; EDM-CUE validates cue-point/phrase prediction on single tracks if you can match Deezer IDs to audio you own.
- Kim 2020's statistics (32-beat phrase periodicity, <5% tempo change in 86% of cases, almost no key shifting) are the best published quantitative priors for house/trance DJ behaviour and can be used directly as design targets.
- The 2.5% key-transposition and <10% tempo-change figures mean fingerprinters tolerant to ~±10% tempo change (KQ7) cover ~95% of real transitions.

### Gaps
- No 2023-2026 DJ-mix dataset from Pioneer DJ/AlphaTheta or the Mixxx community was found; the only post-2022 releases located are EDM-CUE (2024) and Raveform (2026).
- Raveform's dataset licence is not stated on its page or in the article; the GitHub repo could not be read through this proxy.
- Whether the mixotic Google Drive download links still resolve was not tested (only the index page).
- Kim 2020's 1001Tracklists-derived metadata remains private; no later public release was found.

## Key Question 5: Stems and source-separation sets (MUSDB18-HQ, MoisesDB, MedleyDB, Slakh2100, Cambridge-MT, DSD100)

### Takeaway
MUSDB18/MUSDB18-HQ (Zenodo, non-commercial), MoisesDB (240 tracks, CC BY-NC-SA 4.0 via music.ai) and Slakh2100 (Zenodo, CC BY 4.0, synthesized) are all live in 2026; none of the pages retrieved quantifies an electronic/house subset, and no dedicated EDM stem dataset was found. Demucs htdemucs_ft reports 9.0 dB SDR on MUSDB-HQ but the repo was archived on 2025-01-01.

### Cited Findings

## Key Question 7: Fingerprinting / alignment tools under tempo and pitch change (Panako, Olaf, audfprint, dejavu, Chromaprint, Qfp)

### Takeaway
Published tolerances: audfprint (Shazam-style landmarks) breaks beyond ~3% pitch shift and cannot handle combined time-scale (speed) change; Panako handles pitch/time modifications up to roughly 8-10% (AGPL, Java); Sonnleitner's Qfp quad-based method is cited as robust to ±30% and achieved 0.876 accuracy on real DJ mixes vs 0.637 (audfprint) and 0.360 (Panako); Chromaprint/AcoustID was not evaluated here. Given Kim 2020's finding that 94.5% of real tempo adjustments are <10%, Panako-class tolerance covers most but not all transitions.

### Cited Findings
- Panako (Six & Leman, ISMIR 2014): claims handling of "time-scale and pitch modifications of up to ten percent"; performance "decreases with time-scale modification of more than eight percent"; "more than a third of the queries is resolved correctly after a time stretching modification of 8%"; pitch shifts tested -200..+200 cents with dips near ±3% and ±9% due to Constant-Q bin spacing; 100% specificity; evaluated on ~30,000 Jamendo songs with 97,200 query fragments (20/40/60 s, 54 modifications); baseline audfprint "does not recover after pitch-shifts of more than three percent", is "rather robust against time-stretching" but "unable to cope with time-scale modification" — [ISMIR 2014 Panako paper](https://archives.ismir.net/ismir2014/paper/000122.pdf)
- Panako software: Java (JDK 11+, Gradle), AGPL; v2.0 replaced the Constant-Q with a Gabor transform (JGaborator/Gaborator C++ via JNI); bundles an "Olaf" implementation of Wang's 2003 Shazam algorithm, a pitch-class-histogram fingerprinter, and (in v1.6) Haitsma-Kalker and simplified Chromaprint variants; no accuracy numbers on the readme — [Panako readme](https://0110.be/releases/Panako/Panako-latest/readme.html); GitHub — [JorenSix/Panako](https://github.com/JorenSix/Panako); Olaf also has a standalone JOSS paper — [JOSS 10.21105/joss.04554](https://joss.theoj.org/papers/10.21105/joss.04554.pdf)
- Sonnleitner et al. 2016 DJ-mix identification (accuracy / precision / specificity): mixotic set — Qfp 0.876 / 0.959 / 0.927, audfprint 0.637 / 0.680 / 0.255, Panako 0.360 / 0.432 / 0.349; disco set — Qfp 0.741 / 0.917 / 0.942, audfprint 0.419 / 0.513 / 0.487, Panako 0.247 / 0.452 / 0.746; prior evaluations cited: Qfp robust to pitch and/or time-scale changes up to ±30%, Panako up to ~8% — [ISMIR 2016 PDF](https://bpb-us-e1.wpmucdn.com/wp.nyu.edu/dist/2/2294/files/2016/07/187_Paper.pdf); JKU project page — [research.jku.at](https://research.jku.at/en/publications/landmark-based-audio-fingerprinting-for-dj-mix-monitoring/)
- Kim et al. 2020 avoided fingerprinting altogether and used subsequence DTW on beat-synchronous CENS chroma + MFCC, with a key-invariant 12-shift variant, filtering at match rate 0.4 — [ar5iv 2008.10267](https://ar5iv.arxiv.org/html/2008.10267)
- Raveform reused the Kim 2020 alignment method for all 4,902 mixes — [TISMIR 10.5334/tismir.288](https://transactions.ismir.net/articles/288)
- acoustid.org/chromaprint responded HTTP 200 on 2026-10-07 (page content not examined) — [Chromaprint](https://acoustid.org/chromaprint)

### Inferences
- For aligning known tracks into a mix with tempo changes ≤10%, beat-synchronous DTW (Kim 2020) sidesteps fingerprint tolerance limits entirely and additionally yields the warping path needed for transition boundaries; fingerprinting is better reserved for *identifying* unknown tracks, where Qfp-class (±30%) or Panako (≤8-10%) tolerance is required and audfprint/Chromaprint-style methods will miss pitched-up/down tracks.
- Panako's AGPL licence is a constraint for any closed-source product component.

### Gaps
- Licences and current maintenance status of audfprint and dejavu were not verified (GitHub blocked through this proxy); Chromaprint's licence and tempo tolerance were not retrieved.
- Qfp code availability was not confirmed; Sonnleitner's dissertation is at cp.jku.at but was not examined — [Sonnleitner dissertation](https://www.cp.jku.at/research/papers/Sonnleitner_Dissertation.pdf)
- Olaf's standalone licence was not retrieved.

## Key Question 8: Benchmark reference numbers (what "good" looks like) and 2026 liveness summary

### Takeaway
Reference points: Beat This! 89.1/78.3 beat/downbeat F1 on GTZAN and 95.8/90.7 on Harmonix; madmom DBN 0.938/0.863 on Ballroom; edma 57.8% exact (65.6 weighted) and edmm 63.7% (70.1) key accuracy on GiantSteps Key; htdemucs_ft 9.0 dB SDR on MUSDB-HQ. Of the resources checked by HTTP on 2026-10-07, all Zenodo records and the Raveform/EDM-CUE Hugging Face records are alive; the GiantSteps Beatport audio URLs and DISCO-10M are dead.

### Cited Findings
- Beat tracking: Beat This! GTZAN 89.1 ± 0.3 beat / 78.3 ± 0.4 downbeat F1 (%), Harmonix 95.8 / 90.7, Ballroom 97.5 / 95.3, Hainsworth 91.9 / 80.0, SMC 62.7, HJDB 98.2 / 96.6 — [arXiv 2407.21658](https://arxiv.org/pdf/2407.21658)
- madmom DBN downbeat (Böck et al. 2016): Ballroom 0.938 / 0.863, Hainsworth 0.867 / 0.684, Beatles 0.918 / 0.832, RWC Pop 0.943 / 0.861 (beat / downbeat F1) — [ISMIR 2016](https://archives.ismir.net/ismir2016/paper/000186.pdf)
- Key on GiantSteps Key (604 EDM clips): EDMA 65.6 weighted / 57.8% correct; EDMM 70.1 / 63.7%; CNN 74.3 / 67.9%; QM 50.4 / 39.6% — [Korzeniowski & Widmer 2017](https://arxiv.org/pdf/1706.02921)
- Separation: htdemucs_ft 9.0 dB SDR on MUSDB18-HQ test (MIT; repo archived 2025-01-01) — [demucs README](https://github.com/facebookresearch/demucs)
- Drop detection (2014 baseline): F1 0.61 at 3 s → 0.71 at 15 s tolerance on 100 SoundCloud EDM tracks — [Yadati et al. 2014](https://archives.ismir.net/ismir2014/paper/000297.pdf)
- DJ-mix track identification (2016): Qfp 0.876 accuracy on 10 real techno/house mixes vs audfprint 0.637 and Panako 0.360 — [Sonnleitner et al. 2016](https://bpb-us-e1.wpmucdn.com/wp.nyu.edu/dist/2/2294/files/2016/07/187_Paper.pdf)
- DJ behaviour priors (2020): 86.1% of tempo adjustments < 5%, 94.5% < 10%; 2.5% of plays transposed; transition lengths peak every 32 beats; 40.4% of DJ cue-point pairs within 4 beats — [Kim et al. 2020](https://ar5iv.arxiv.org/html/2008.10267)
- Liveness observed 2026-10-07 (HTTP status from this environment): 404 — geo-samples.beatport.com GiantSteps LOFI previews (two files); 401 — HF DISCOX/DISCO-10M; 200 — Zenodo 1422385 (UnmixDB), 1101082 (Beatport EDM Key), 1095691 (GiantSteps+ Key), 3338373 (MUSDB18-HQ), 1117372 (MUSDB18), 4599666 (Slakh2100), 3826813 (MTG-Jamendo metadata), 13922116 (Beat This! spectrograms); 200 — HF taejunkim/raveform (zip), disco-eth/edm-cue, laion/LAION-DISCO-12M; 200 — cp.jku.at/datasets/fingerprinting, magenta.tensorflow.org/datasets/groove, medleydb.weebly.com, acoustid.org/chromaprint, os.unil.cloud.switch.ch/fma/fma_metadata.zip, mir-aidj.github.io/raveform; 403 (proxy, unverifiable) — all github.com URLs and cambridge-mt.com; 404 — anasynth.ircam.fr ENST-drums legacy URL; connection failure — salami.music.mcgill.ca. (Primary sources for each resource are cited in KQ1-KQ7.)

### Inferences
- A house-focused pipeline should target ≥95% beat / ≥90% downbeat F1 on Raveform-style EDM (Beat This! Harmonix/HJDB level), ≥64% exact key on Beatport key sets (edmm level), and mix-in/mix-out estimates within 4 beats for ≥40% of transitions (the inter-DJ agreement ceiling from Kim 2020) — beyond that you are exceeding human-DJ consistency.
- Because the GiantSteps audio is dead, any 2026 tempo/key benchmark must be rerun on the Zenodo Beatport key sets (audio included) or on Raveform's corrected tempo subset, and papers' GiantSteps-Tempo numbers can no longer be reproduced without archived audio.

- No essentia-version-specific `edma` figure beyond the Korzeniowski re-evaluation was found; essentia's own documentation page was not read for accuracy claims.
- Harmonix YouTube link rot, Cambridge-MT status, and GitHub repository status could not be verified from this environment.
