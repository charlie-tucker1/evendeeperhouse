# Metadata, Tracklist, and Crowd-Reaction Data Sources for AI DJ-Transition Research (status as of 2026-10-07)

Scope note: this file covers (a) where to learn which tracks appear where in recorded DJ sets, (b) services that identify tracks and align them into mixes, and (c) timestamped crowd-reaction signals. Everything was checked live on 2026-10-07 from a US-based cloud environment behind a datacenter proxy; where a site blocked the fetcher this is stated, because it is itself evidence about how scraper-hostile the source is. Facts older than 2025 are dated. The user is a personal, non-commercial researcher; ToS clauses are quoted verbatim wherever a page could be read.

---

## Key Question 1: 1001Tracklists — official API, fields, ToS, community scrapers, coverage

### Takeaway
There is no public or documented 1001Tracklists API in 2026; the only known third-party data recipient is Songstats under an exclusive arrangement, and the site's content pages actively block non-browser clients (HTTP 403 / TCP reset during this research). Community scrapers exist but are small, undated, and the most current open-source tool (Aug 2026) treats 1001Tracklists as blocked and routes around it via "unblocked web mirrors."

### Cited Findings
- The 1001Tracklists homepage footer, fetched 2026-10-07, contains Privacy, FAQ, Newsletter, What's New, Advertise (Google Form), DJ Promo (Google Form), Contact, and Tracklist Groups links; it contains no Terms of Service, API, partner, or data-licensing link — [1001Tracklists homepage](https://www.1001tracklists.com/)
- The FAQ has no entries on API access, data licensing, scraping/automated access, "ID" placeholders, timestamps, or media links; it states "Standard users can submit tracklists" (standard status is reached by correctly identifying 5 tracks) and "We manually validate tracks after they've been played in tracklists that get added" — [1001Tracklists FAQ](https://www.1001tracklists.com/info/faq.html)
- Direct fetches of https://www.1001tracklists.com/terms/ returned HTTP 404; the privacy page (https://www.1001tracklists.com/info/privacy.html), a tracklist page, and the Deep House genre index all returned HTTP 403 to the research fetcher on 2026-10-07, while the homepage and FAQ returned 200. Plain `curl` requests to any 1001tracklists.com URL (including robots.txt) were reset at the TCP level ("Recv failure: Connection reset by peer"). — observed during this research; see URLs above
- Songstats (Oct 2020): 1001Tracklists track-to-tracklist data "is provided to Songstats exclusively." The article does not describe a public API or any other third-party recipient — [Songstats Lab, "1001Tracklists: The Importance of DJ Support"](https://lab.songstats.com/1001tracklists-the-importance-of-dj-support-84b0a5ed3590)
- Community scraper `yss14/1001tracklist-api` (TypeScript, MIT): "A small REST API providing some functionality to fetch data from 1001tracklist.com." Endpoints: `/tracklists?query=` returns `{title, link}` per result; `/tracklist/tracks?tracklistURL=` returns `{trackTitle: string, timestamp: number|null}` per track. 8 commits; no release; last-commit date not shown on the page; no Cloudflare/blocking notes — [GitHub yss14/1001tracklist-api](https://github.com/yss14/1001tracklist-api)
- Community scraper `spandya108/1001tracklistutils` (Python): `scrape.py` performs "the website scraping" and writes only track names for an "artist edc year" search; no timestamps, IDs or media links; 12 commits, last-commit date not shown — [GitHub spandya108/1001tracklistutils](https://github.com/spandya108/1001tracklistutils)
- `fetch-mix-cli` (Go, MIT, v1.0.2 published Aug 23, 2026, "intended for non-commercial use"): for 1001Tracklists it "extracts the set slug from the URL and searches for 'unblocked web mirrors'" rather than scraping the site directly; it names OpeningTrack, Tracklist.club and Thomas Laupstad as "crawlable tracklist web mirrors" (queried via WordPress REST APIs); MixesDB is searched "through its MediaWiki Search API"; YouTube top comments (up to 500) are fetched with `yt-dlp` and screened for tracklist comments by an LLM with a regex fallback — [pkg.go.dev fetch-mix-cli](https://pkg.go.dev/github.com/alexgorbatchev/fetch-mix-cli); [GitHub alexgorbatchev/fetch-mix-cli](https://github.com/alexgorbatchev/fetch-mix-cli)
- Coverage signal: a site-restricted search on 2026-10-07 surfaced a Deep House genre index (https://www.1001tracklists.com/genre/deep-house/index.html), a tracklist group "Deep Progressive Melodic House/Techno Sets" (https://www.1001tracklists.com/groups/ltsvsd/deep-progressive-melodic-house-techno-sets/index.html), and tracklists dated 2026-10-07 (e.g., "Steve Kelley - Celestial 2026-10-07", "Cloudcage - Monstercat Silk Showcase 874 2026-10-07") plus "Above & Beyond @ Deep Set, ABGT 700 ... 2026-09-11" and "James Hype @ Deep House Mix For The Gym 2026-06-01" — [1001Tracklists search results via WebSearch, 2026-10-07](https://www.1001tracklists.com/genre/deep-house/index.html)
- Related tool: `tracklistify` (community project) builds tracklists from DJ-mix audio via recognition services rather than scraping 1001Tracklists — [gitblind mirror of betmoar/tracklistify](https://gitblind.noratr.app/betmoar/tracklistify) (mirror page; original repo not fetched)

### Inferences
- Because no Terms page could be located (404 at /terms/, no footer link, privacy page 403), the user cannot rely on a quotable scraping clause; but the technical posture (403 on content pages, TCP resets to curl, and third-party tools explicitly designed to avoid the site) is strong evidence that 1001Tracklists does not want automated access. Treat scraping as both technically fragile and against the operator's evident intent.
- The `yss14` schema (`timestamp: number|null`) confirms that 1001Tracklists tracklists carry optional per-track cue timestamps that are frequently null; the community understands cue times as sparse.
- Deep/melodic/tech house coverage is clearly present (dedicated genre index and a melodic-house/techno tracklist group with entries updated the day of research), but absolute counts could not be read because the genre page returned 403.
- The "mirror" ecosystem (OpeningTrack, Tracklist.club) that fetch-mix-cli relies on is itself of unknown legality and persistence; it is not a stable research substrate.

### Gaps
- Could not locate or quote a 1001Tracklists Terms of Use (404/403). The operating entity and governing law are therefore unverified.
- No evidence of a paid/partner API or its pricing beyond the 2020 Songstats exclusivity statement; whether other licensees exist is unknown.
- Could not verify whether the yss14 or spandya108 scrapers still work in 2026 (GitHub API search was unavailable in this environment; last-commit dates were not rendered).
- The FAQ does not define "ID"; the conventional meaning (unidentified track placeholder, "ID - ID") is community knowledge, not documented on the page read.

## Key Question 2: MixesDB — 2026 status, data, archive/dump, Raveform usage

### Takeaway
MixesDB announced permanent closure for 29 June 2024 but was rescued by a new team (relaunched as Mixes.wiki in July 2024) and, as of 2026-10-07, is live again at www.mixesdb.com on MediaWiki 1.46.1 with a working MediaWiki API, 370,131 mix pages, and daily edits; the mixes.wiki hostname no longer resolved during this research. No official data dump was ever announced, but the MediaWiki API (robots.txt Crawl-delay 4) is a practical bulk-access route, and the Raveform (TISMIR 2026) dataset was built almost entirely from MixesDB metadata.

### Cited Findings
- Closure announcement (DJ Mag, 5 June 2024): site to go offline permanently on Saturday 29 June 2024; the operator's note said the code "cannot be run on modern servers anymore," ad revenue had dropped to near zero, and donations had failed; users were advised to copy what they needed; no data dump/export was mentioned; the site launched December 2006 — [DJ Mag](https://djmag.com/news/mixesdb-long-running-mix-database-shut-down-after-20-years)
- Relaunch (The Quietus, 4 July 2024): a new team worked with the former owner "to take over the code and data and upgrade the software"; new site Mixes.wiki at https://www.mixes.wiki/w/Main_Page; no API/open-data statement — [The Quietus](https://thequietus.com/?p=249818)
- 45rpm.ch (9 July 2024): "MixesDB stays and is now called Mixes.wiki"; over 200,000 DJ sets across 100 genre categories "preserved"; no API/export mentioned — [45rpm.ch news](https://45rpm.ch/kategorie/news); the same outlet's MixesDB category page has no 2025–2026 items — [45rpm.ch MixesDB category](https://45rpm.ch/kategorie/mixesdb/)
- Live status 2026-10-07: `https://www.mixesdb.com/` returned HTTP 200 and redirected to `/w/Main_Page`; page generator meta = "MediaWiki 1.46.1"; on-page stats: "370,131 mix pages in 88,033 categories"; "Latest mixes" list shows entries added 2026-10-07; style menu includes House, Deep House, Minimal House, Minimal Tech House, Tech House / Electro, Techno / Acid — [MixesDB Main Page](https://www.mixesdb.com/w/Main_Page)
- Live MediaWiki API 2026-10-07: `api.php?action=query&meta=siteinfo` returned `"sitename":"MixesDB"`, `"generator":"MediaWiki 1.46.1"`, `"server":"https://www.mixesdb.com"`, `"writeapi":""` (enabled), statistics `pages 773057, articles 97304, edits 1050499, images 158889, users 3168, activeusers 171, admins 4`, and `rightsinfo: {"url":"","text":""}` (no content license declared) — [MixesDB api.php siteinfo](https://www.mixesdb.com/w/api.php?action=query&meta=siteinfo&siprop=general|statistics|rightsinfo&format=json)
- Genre category sizes 2026-10-07 (api.php `prop=categoryinfo`): Category:House 127,836 pages; Category:Techno 79,517; Category:Tech House 68,024; Category:Deep House 31,597; Category:Minimal 18,144; Category:Melodic Techno and Category:Melodic House do not exist (`"missing"`) — [MixesDB api.php categoryinfo](https://www.mixesdb.com/w/api.php?action=query&prop=categoryinfo&titles=Category:Deep_House|Category:Tech_House|Category:Melodic_Techno|Category:Melodic_House|Category:House|Category:Techno|Category:Minimal&format=json)
- Tracklist-completeness categories 2026-10-07: "Tracklist: complete" 150,604 pages; "Tracklist: incomplete" 135,176; "Tracklist: none" 77,771 — [MixesDB api.php categoryinfo](https://www.mixesdb.com/w/api.php?action=query&prop=categoryinfo&titles=Category:Tracklist:_complete|Category:Tracklist:_incomplete|Category:Tracklist:_none&format=json)
- Tracklist wikitext format (sample page "2026-09-04 - Alle Farben - Energy Extravadance", retrieved via `action=parse&prop=wikitext`): `== Tracklist ==` followed by numbered lines like `# Beth Lydi - Parallel In Time (Cascandy Remix) [Snoe]`, plus categories `[[Category:Deep House]]`, `[[Category:Tracklist: complete]]`; no timestamps on this page — [MixesDB api.php parse](https://www.mixesdb.com/w/api.php?action=parse&page=2026-09-04_-_Alle_Farben_-_Energy_Extravadance&prop=wikitext&format=json)
- Timestamped tracklists use `[h:mm:ss]` prefixes and `?` for unidentified tracks, e.g. `# [0:00:00] My Bloody Valentine - Soon (Andrew Weatherall Remix)` / `[0:07:36] ?`; a CirrusSearch for `insource:"[0:00]" incategory:"Deep_House"` returned `totalhits: 160` — [MixesDB api.php search](https://www.mixesdb.com/w/api.php?action=query&list=search&srsearch=insource:%22%5B0:00%5D%22+incategory:%22Deep_House%22&format=json)
- robots.txt (2026-10-07): `User-Agent: *`, `Crawl-delay: 4`, Disallow includes `/w/Special`, `/*?action=`, `/*?title=`, `/*.mp3`, `/db/`, `/tools/`, and many player/host categories (`/w/Category:SoundCloud`, `/w/Category:YouTube`, `/w/Category:Mixcloud`, ...) — [MixesDB robots.txt](https://www.mixesdb.com/robots.txt)
- Raveform (Kim, Kim, Kim, Nam; TISMIR vol. 9 no. 1, pp. 131–143, DOI 10.5334/tismir.288; submitted 10 Jun 2025, accepted 9 Jan 2026, published 20 Apr 2026): "nearly all data, except the structural annotations, came from MixesDB" (mix metadata, mix audio links, links to played tracks); authors used MixesDB's filtering feature and note tracklists "can be inaccurate, such as listing a different version of a track than the one played"; track audio came from YouTube; scale: 4,902 mixes, 56,873 unique tracks (73,505 played-track instances), ~6,522 hours of mixes, 53,780 available transitions, 1,423 tracks with structural annotations; only 342 mixes (7%) fully identified; mix-in/mix-out positions were NOT manually annotated but estimated by beat-level mix-to-track alignment (Kim et al. 2020) with match-rate <0.1 discarded; genres: techno most common, then trance, drum and bass, house; annotated tracks: techno, trance, DnB, tech house, mainstage (genre labels from Beatport tags); tempo peaks at 128 BPM with secondary cluster at 170–175; dataset/models at https://mir-aidj.github.io/raveform/; article CC BY 4.0, no separate dataset license stated; no ToS discussion — [TISMIR article 288](https://transactions.ismir.net/articles/288)
- fetch-mix-cli (Aug 2026) queries MixesDB "through its MediaWiki Search API" and scrapes "raw wikitext" — [pkg.go.dev fetch-mix-cli](https://pkg.go.dev/github.com/alexgorbatchev/fetch-mix-cli)

### Inferences
- MixesDB is the most research-friendly set-level tracklist source in 2026: it is live, MediaWiki-based (standard `api.php`, `action=parse&prop=wikitext`, `list=categorymembers`, CirrusSearch), and its robots.txt sets an explicit crawl rate (one request per 4 s) rather than banning bots. A full dump of ~370k pages at that rate is roughly 17 days of polite crawling.
- The absence of a declared license (`rightsinfo` empty) means MixesDB content is user-contributed with unspecified rights; redistribution should be avoided, which matches the user's "no redistribution" constraint.
- Explicit per-track timestamps are a minority of MixesDB tracklists (the narrow `[0:00]` search found 160 Deep House pages out of 31,597); Raveform confirms that even "complete" tracklists are rarely fully resolvable to playable audio (7% of mixes fully identified), so audio alignment (not metadata) is what yields transition timestamps.
- The 2024 "shutdown" narrative in press is stale; a report should say "announced closure June 2024; rescued July 2024 as Mixes.wiki; back on mixesdb.com in 2026."

### Gaps
- No announcement explaining the move back from mixes.wiki to mixesdb.com was found; mixes.wiki failed DNS resolution and proxy CONNECT (502) from this environment, which could be a local network artifact. Flag as "domain status uncertain."
- No official data dump/XML export was found for either the 2024 closure or the current site; Internet Archive could not be queried (web.archive.org blocked by egress policy here).
- Raveform's dataset license and whether it redistributes MixesDB metadata (vs. only annotations) were not stated in the article text read.
- The discrepancy between "370,131 mix pages" (site banner) and `articles: 97304` (api statistics) was not resolved; MediaWiki's `articles` counter uses its own content-page definition.

## Key Question 3: Release/track metadata alternatives (Discogs, MusicBrainz, Beatport, Spotify, Deezer, Apple Music, SoundCloud, YouTube, Mixcloud, RA, Bandcamp, Audius)

### Takeaway
Free, well-documented, research-usable metadata APIs in 2026 are Discogs (60 req/min authenticated, CC0 monthly dumps), MusicBrainz (1 req/s, DJ-mix release-group type), and Deezer's public track object (BPM, gain, ISRC); Spotify has effectively closed to individual researchers (audio-features/analysis removed for new apps Nov 2024; Premium-only 5-user Development Mode since Feb–Mar 2026; Extended Quota only for registered businesses with 250k MAU since May 2025); Beatport v4 has no normal developer sign-up; SoundCloud reopened self-serve API keys in May 2026 but only for Artist Pro subscribers and with a ToS that bars scraping, caching, and AI training; Mixcloud's API exposes no comments and no readable tracklist sections.

### Cited Findings
**Discogs**
- "Authenticated requests are limited to 60 per minute, and unauthenticated requests ... are limited to 25 per minute, with some exceptions"; "moving average over a 60 second window"; headers `X-Discogs-Ratelimit`, `X-Discogs-Ratelimit-Used`, `X-Discogs-Ratelimit-Remaining`; "To easily access your own user account information, use a User token" (personal access token); consumer key/secret for 3rd-party apps; release tracklist entries carry `duration`, `position`, `title`, `type_`, optional `extraartists`; "Some Discogs data is made available under the CC0 No Rights Reserved license" with the rest restricted under the API Terms of Use; "Our monthly data dumps are available under the the CC0 No Rights Reserved license" — [Discogs API docs](https://www.discogs.com/developers)
- Discogs forum users report ~20–30 image requests/min via Cloudflare with an "unknown and unpublished formula" (user observations, not staff) — [Discogs forum thread 997721](https://www.discogs.com/forum/thread/997721)
- The Discogs API Terms of Use support article returned HTTP 403 to this fetcher — [Discogs API Terms of Use](https://support.discogs.com/hc/en-us/articles/360009334593-API-Terms-of-Use)

**MusicBrainz**
- Per-IP rule: "Currently that rate is (on average) 1 request per second"; exceeding it returns 503 for all requests until the rate drops; global cap 300 req/s; anonymous/generic User-Agents (blank, Java, Python-urllib, Apache-HttpClient) are throttled to ~50 req/s shared; User-Agent must contain enough information to contact the maintainers (rules dated 2012-01-08, page current) — [MusicBrainz API Rate Limiting](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)
- Release-group secondary types include "DJ-mix" (3.9) and "Mixtape/Street" (3.10), alongside "Remix", "Live", etc. — [MusicBrainz Release Group/Type](https://musicbrainz.org/doc/Release_Group/Type)

**Beatport**
- beets-beatport4 README: Beatport "API v3 was discontinued"; it is "not possible to request API access the 'normal' way" (client credentials or Beatport-issued token), so the plugin scrapes a public client ID from Beatport's Swagger docs frontend and uses OAuth authorization_code with the user's Beatport username/password or a browser-captured `/v4/auth/o/token/` response; metadata exposed includes genre/sub-genre, release date, label, catalog number; BPM/key not mentioned on the page — [GitHub Samik081/beets-beatport4](https://github.com/Samik081/beets-beatport4)
- Music Assistant discussion (Jun–Nov 2025): v4 docs at api.beatport.com/v4/docs/; a partner portal with a request form exists; a commenter (Nov 1, 2025) claims Beatport "can provide a official client_id and client_secret" on application; maintainers declined integration citing no streaming endpoints and ToS uncertainty: "If you can show how this is legally allowed and within the Beatport TOS then we will look more into it." No Beatport statement appears — [music-assistant discussion #4039](https://github.com/orgs/music-assistant/discussions/4039)

**Spotify**
- 27 Nov 2024 (effective same day): "new Web API use cases will no longer be able to access or use the following endpoints and functionality": Related Artists, Recommendations, Audio Features, Audio Analysis, Get Featured Playlists, Get Category's Playlists, 30-second preview URLs in multi-get responses, Algorithmic and Spotify-owned editorial playlists; applies to apps registered on/after that date and to development-mode apps without a pending extension request; "existing extended mode apps remain unaffected"; reason: "To increase security we are limiting access to certain Web API endpoints for new applications" — [Spotify Developer blog, 2024-11-27](https://developer.spotify.com/blog/2024-11-27-changes-to-the-web-api)
- 6 Feb 2026 update: from Wednesday 11 February for new Client IDs, "Development Mode use will require a Spotify Premium account", "Developers will be limited to one Development Mode Client ID", "Each Client ID will be limited to up to five authorized users", and access is restricted to a smaller supported-endpoint set; Premium/5-user/one-ID rules apply to all existing Development Mode integrations from March 9; endpoint restrictions for existing apps were postponed after community feedback — [Spotify Developer blog, 2026-02-06](https://developer.spotify.com/blog/2026-02-06-update-on-developer-access-and-platform-security)
- Quota modes page: "Up to 5 authenticated Spotify users can use an app that is in development mode"; "The app owner must have a Spotify Premium account for apps in development mode to function"; "as of May 15th 2025, Spotify only accepts applications from organizations (not individuals)" for Extended Quota Mode, requiring an "Established Business Entity (legally registered business or organisation)", a launched service, at least 250k MAUs, and commercial viability — [Spotify quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes)
- TechCrunch coverage of the Feb 2026 change — [TechCrunch, 2026-02-06](https://techcrunch.com/2026/02/06/spotify-changes-developer-mode-api-to-require-premium-accounts-limits-test-users/embed/)

**Deezer**
- The public Track resource (as wrapped by deezer-python) exposes `bpm` (float), `gain` (float), `duration`, `isrc`, `release_date`, `preview`, `rank`, `title_version`, `contributors`, etc. — [deezer-python Track reference](https://deezer-python.readthedocs.io/en/latest/api_reference/resources/track.html)

**Apple Music**
- Apple Developer Forums (Sep 2020): creating a MusicKit identifier and private key for developer tokens happens in Certificates, Identifiers & Profiles, and "access to C,I&P requires a paid Apple Developer Program account" (user answer; 2020, may be stale) — [Apple Developer Forums thread 661313](https://developer.apple.com/forums/thread/661313)

**SoundCloud (official API)**
- History: on 23 Sep 2016 SoundCloud closed self-serve keys: "developers will need to fill out an application form to request access to our API"; "All new requests for an API key must go through the review process" — [SoundCloud blog, API Sign-up Changes](https://developers.soundcloud.com/blog/api-sign-up-changes)
- 18 May 2026: self-serve returned for paying creators: "you can now instantly generate your own Client ID and Client Secret via our fully self-service portal"; previously access was via the chatbot "Otto"; no chatbots, manual review forms, or waiting periods — [SoundCloud blog, Vibe Coding / self-serve API keys](https://developers.soundcloud.com/blog/vibe-coding-ai-agent-docs-self-serve-api-keys); third-party commentary — [API Evangelist, 2026-06-19](https://apievangelist.com/2026/06/19/soundcloud-shows-what-programmatic-api-onboarding-should-look-like/)
- Register-app page: "You need a SoundCloud Artist Pro subscription to register API applications and receive credentials"; "Make sure your account is on Artist Pro before continuing"; CLI script `sc-api-auth.mjs` (Node 18+) also available — [SoundCloud register-app](https://developers.soundcloud.com/docs/api/register-app)
- API Guide: "All API usage requires a registered application: Get an API key — create a SoundCloud account (Artist Pro required)"; Client Credentials token limits "50 tokens per 12 hours per application" and "30 tokens per 1 hour per IP address" — [SoundCloud API Guide](https://developers.soundcloud.com/docs/api/guide)
- Rate limits page: play stream requests "15,000 per 24-hour window" (only `/tracks/:id/stream`); client-credentials tokens "50 per 12 hours per app, 30 per hour per IP"; global aggregate limit "Not currently enforced"; exceeding returns HTTP 429 with reset time — [SoundCloud rate limits](https://developers.soundcloud.com/docs/api/rate-limits)
- Official OpenAPI spec (embedded in the API Explorer's swagger-ui-init.js) defines `GET /tracks/{track_urn}/comments` ("Returns the comments posted on the track(track_urn)") with parameters `track_urn`, `limit`, `offset`, `linked_partitioning`; the `Comment` schema has `body`, `created_at`, `urn`, `kind`, `user_urn`, `timestamp` ("Timestamp.", type string; example value `4960`), `track_urn`, `uri`, `user` — [SoundCloud API Explorer (OpenAPI)](https://developers.soundcloud.com/docs/api/explorer/open-api)
- API Guide on timed comments: "Include a timestamp parameter (in milliseconds from track start) for a timed comment. Omitting it creates a non-timed comment." — [SoundCloud API Guide](https://developers.soundcloud.com/docs/api/guide)
- API Terms of Use (Effective Date: 30 March 2024): General Prohibitions item 4: "You must not employ scraping or similar techniques to copy, aggregate, repurpose, republish"; Content Use: "Copy or reproduce any User Content for the purposes of informing, training, developing" ... "(a) to train or otherwise develop any artificial intelligence technology"; Caching: "Your app may employ session-based caching, but only to the extent reasonably necessary" and "any cached content must cease to be available, accessible or playable within your app at the end of that session"; "Your app must not include file-save functionality, or otherwise designed to cache, download"; User Content is defined as "All audio, text, images, comments and other data or information associated with user accounts"; Personal Data includes "any comments or posts by that user"; "Access to the SoundCloud API is currently provided free of charge"; no research/academic clause — [SoundCloud API Terms of Use](https://developers.soundcloud.com/docs/api/terms-of-use)
- Unofficial route: `soundcloud.ts` uses SoundCloud's internal v2 endpoints with a client_id taken from browser network traffic ("Soundcloud has closed down their API applications"); exposes `tracks.comments()` and a `SoundCloudComment.timestamp: number`; the repository "was archived by the owner on Sep 12, 2026" — [GitHub Moebits/soundcloud.ts](https://github.com/Moebits/soundcloud.ts)

**YouTube Data API v3** (metadata part; comment specifics in Q5)
- Default quota: "projects that enable the YouTube Data API have a default quota allocation of 100 search.list calls, 100 videos.insert calls, and 10,000 units per day combined for all other endpoints"; `commentThreads.list` = 1 unit; `comments.list` = 1; `videos.list` = 1; `playlistItems.list` = 1; `search.list`: "100 quota per day. Each call costs 1 quota."; quotas reset at midnight Pacific — [YouTube Data API quota costs](https://developers.google.com/youtube/v3/determine_quota_cost)

**Mixcloud**
- Reads need no authentication; writes need OAuth 2.0 ("Only browser-based authorization is supported"); endpoints: `/search/` (`type=cloudcast|user|tag`), `/popular/`, `/new/`, user connections (followers, favorites, cloudcasts, listens), embeds; "Audio streams are not available through the Mixcloud API"; no comments endpoint is documented (comments appear only as a rate-limit category); tracklist sections are writable on upload/edit via `sections-X-artist`, `sections-X-song`, `sections-X-chapter`, `sections-X-start_time` (whole seconds) but no documented way to read sections back; rate limits are unpublished, exceeding returns HTTP 403 `RateLimitException` with `Retry-After`; higher limits "on request through support" — [Mixcloud developers](https://www.mixcloud.com/developers/)

**Resident Advisor**
- Searches for an RA API surfaced only commercial Apify scrapers (events, lineups, clubs), no official developer documentation — e.g. [Apify: Resident Advisor Events Scraper](https://apify.com/bovi/residentadvisor-events-scraper)

**Audius**
- Developer landing page: the REST API lets you "Query, stream, and search for tracks, users & playlists across the network"; API reference at docs.audius.co/api; protocol docs at docs.openaudio.org — [Audius developers](https://docs.audius.co/developers/guides/rest-api)

### Inferences
- For a US individual researcher in 2026, Spotify is not a viable metadata/analysis source: individuals cannot get Extended Quota, and Development Mode is capped at 5 users and requires Premium; audio-features/analysis are gone for any new app.
- Deezer's public `bpm`/`gain` fields are the only remaining free, no-auth tempo field among major DSPs found here (used by EDM-CUE per the task brief; not independently verified in this research).
- Beatport metadata (genre/sub-genre/label) is reachable only through credential-scraping workarounds whose ToS compliance is doubted even by open-source maintainers; it should not be a dependency.
- SoundCloud's official API now (May 2026+) gives a paying Artist Pro subscriber instant credentials and an official `GET /tracks/{urn}/comments` endpoint with millisecond `timestamp` — but the ToS forbids retaining content across sessions and any AI-training use of User Content (comments included). This is the central legal tension for using timed comments as training signal; see Q6.
- Mixcloud is a poor source for both tracklists (sections not readable) and reactions (no comments endpoint).

### Gaps
- Deezer API 2026 status (registration requirements, whether new app creation is still open, any deprecation of `bpm`) was not verified from developers.deezer.com (not fetched); only the Python wrapper's field list was confirmed.
- Apple Music API: current pricing/requirements not verified from Apple docs (only a 2020 forum answer); Apple Music API does not appear in any source read as exposing BPM.
- Resident Advisor: existence of a GraphQL endpoint (ra.co/graphql) and RA's ToS on scraping were not verified — no primary source read.
- Bandcamp: not researched beyond the brief's premise (no public API); no source read.
- Audius: API-key/rate-limit/comment-timestamp details were not extractable (landing pages only).
- Beatport partner-portal URL and application criteria were not read first-hand.
- Discogs API Terms of Use text (commercial-use and retention clauses) could not be quoted (403).

## Key Question 4: Track identification / alignment services (AcoustID/Chromaprint, Shazam, ACRCloud, Audible Magic, Pex)

### Takeaway
AcoustID is free for non-commercial use (API key, 3 req/s) but is a whole-file lookup designed for exact recordings, not tempo-shifted mix segments; Shazam has no official API (shazamio is a reverse-engineered MIT client with no ToS disclaimer); ACRCloud is the only commercial service with a documented multi-song "Traverse Scanning" file mode and a derivative-works (sped-up/pitch-shifted) option, but publishes no price list (14-day trial, per-recognition / per-scanned-hour usage pricing via console); Pex (now part of Vobile) explicitly claims robustness to "speed and pitch changes to remixes" but is enterprise/contact-sales; no concrete Audible Magic pricing or DJ-mix capability was found.

### Cited Findings
**AcoustID / Chromaprint**
- Applications must register for an API key (`client` parameter); "Do not make more than 3 requests per second"; lookup endpoint `https://api.acoustid.org/v2/lookup` with `client`, `duration` (length of "the whole audio file" in seconds), `fingerprint` (Chromaprint); returns AcoustID track `id` + `score`, and with `meta=recordingids`/`recordings` returns MusicBrainz recording IDs and metadata; "No commercial usage" — commercial users directed to acoustid.biz; database is crowd-sourced, no database license stated on the page — [AcoustID web service](https://acoustid.org/webservice)

**Tempo/pitch robustness (academic)**
- Sonnleitner & Widmer (DAFx-14, 2014): Shazam-style landmark systems "depend on equal relative distances of reference and query features to find matches," limiting robustness under scale changes; their quad-based method reports "near perfect overall performance" for speed within 90–115% and tempo within 80–120%; DJ sets are an explicit target ("DJ set track identification", "DJ set monitoring and original track identification"); preliminary tests on DJ sets and broadcast data "found no cases exceeding 7% speed or tempo modification"; a DJ's blending may produce scale changes that are not constant over a song. Chromaprint is not discussed — [Sonnleitner & Widmer, DAFx-14](https://www.dafx14.fau.de/papers/dafx14_reinhard_sonnleitner_quad_based_audio_fingerpr.pdf)

**Shazam (unofficial)**
- ShazamIO: "a FREE asynchronous library from reverse engineered Shazam API"; `await shazam.recognize("file.ogg")` accepts path/bytes; 410 commits; no releases listed; MIT license; "Shazam retired the search endpoints"; no disclaimer about Shazam's terms; no rate-limit/ban notes on the page — [GitHub shazamio/ShazamIO](https://github.com/shazamio/ShazamIO)

**ACRCloud**
- Pricing page publishes no figures: "Flexible pricing models ensuring you only pay for the recognition you use"; "Start Free Trial", "No credit card required to start" — [ACRCloud pricing](https://www.acrcloud.com/pricing/)
- Docs (llms-full): free trial "14 days after registration"; File Scanning accepts audio/video files and URLs from YouTube, TikTok, Facebook, Instagram, Twitter; "Choose Traverse Scanning if you want to scan the entire file for multiple songs in different parts of the file" (vs. Points Scanning for single-song files); Music/Speech Detection flags unrecognised music segments; SDKs recognise one 10-second clip per request (Go SDK default 10 s, max 12 s); identification API: files under 15 seconds work better; responses include `play_offset_ms`; "Derivative Works Detection" covers "sped up/down, pitch shifting content" (test up to 10 files; commercial use requires contacting ACRCloud); Cover Song Identification handles covers/live/humming; "Offline recognition" pricing: "Please contact us to let us evaluate the pricing for you" — [ACRCloud docs llms-full.txt](https://docs.acrcloud.com/llms-full.txt)
- apis.io summary (undated): Music Recognition and Custom Audio Recognition are "usage-based per recognition"; File Scanning is "usage-based per scanned hour"; Broadcast Monitoring "approx US$26 per stream per month (representative)"; no monthly minimum stated; "ACRCloud does not publish a single fixed public price list" — [apis.io ACRCloud plans](https://apis.io/plans/acrcloud/acrcloud-plans-pricing/)
- hearthis.at guest post on ACRCloud's blog (undated): uploads are split into 20-second segments, ~170,000 segments analysed daily via the Python SDK; tracklists with start/end points appear "only minutes after uploading" and work "even with pitch shifts"; promotional, no metrics, no pricing — [ACRCloud blog: generate tracklist of mixes](https://blog.acrcloud.com/avoid-copyright-infringement-generate-tracklist-mixes-mashups-music-streaming-services)

**Pex**
- Platforms page: identifies "recordings, cover songs, live performances, and AI-generated songs"; registry "120M+ recordings" incl. Sony, Universal, Warner; "From speed and pitch changes to remixes, cover versions, and live performances…modified audio is no problem"; "Software development kit and API keys provided" but only "Get a demo"/"Contact us" CTAs; no published prices; banner notes Pex has joined Vobile — [Pex platforms](https://pex.com/use-cases/platforms)

**Audible Magic**
- Searches returned only decades-old press releases and generic datasheets; no pricing, API sign-up, or DJ-mix product page was found — e.g. [Audible Magic core technology datasheet (2015)](https://www.audiblemagic.com/wp-content/uploads/2015/04/AM_overview_datasheet_150406.pdf)

### Inferences
- AcoustID is appropriate for identifying individual *source tracks* the researcher already has as files (whole-file fingerprints → MusicBrainz IDs), not for scanning mixes; its 3 req/s and non-commercial licence suit a personal project.
- For scanning mixes, ACRCloud's Traverse Scanning or a DIY loop of 10–20 s segment lookups with `play_offset_ms` is the practical commercial path; cost must be obtained from the logged-in console, since neither the public pricing page nor docs state per-hour rates.
- Standard fingerprinters (Shazam-style, and by the same mechanism Chromaprint) degrade under tempo change, but DJ-set tempo changes are typically ≤7%, within the tolerance of scale-robust methods and apparently within ACRCloud/Pex derivative-work modes; this is an inference from Sonnleitner & Widmer plus vendor claims, not a tested result.
- Using shazamio against Shazam's private endpoints is unlicensed; the project carries no ToS disclaimer and Shazam has already retired some endpoints, so it is operationally and legally fragile.

### Gaps
- No concrete ACRCloud per-hour or per-request price could be read from any public page (requires console login).
- Chromaprint's own tempo tolerance was not documented in any source read; the inference above rests on the DAFx-14 analysis of landmark systems.
- Audible Magic: no current product/pricing/API information found.
- Pex: no per-hour pricing; whether individual researchers can obtain API keys is unknown (appears enterprise-only).
- Apple's Shazam ToS text was not retrieved.

## Key Question 5: Crowd-reaction / "this moment landed" signals (SoundCloud timed comments, YouTube comments, YouTube Most Replayed heatmap, Mixcloud, Reddit, research)

### Takeaway
Two timestamp-bearing engagement signals are reachable at scale in 2026: SoundCloud timed comments (official API, millisecond `timestamp`, Artist Pro required; or unofficial v2) and YouTube Most Replayed heatmaps (100 normalised bins exposed by yt-dlp's `heatmap` field via InnerTube `MARKER_TYPE_HEATMAP`), plus YouTube comment text containing h:mm:ss timestamps (Data API, 1 unit per 100 top-level comments, 10,000 units/day). Peer-reviewed work shows these are noisy: only ~20% of SoundCloud "drop" comments sit on the actual drop (Yadati et al., ISMIR 2014), and Most Replayed curves are near-unpredictable from video content alone (Duico et al., 2023).

### Cited Findings
**SoundCloud timed comments**
- Official API: `GET /tracks/{track_urn}/comments` with `limit`, `offset`, `linked_partitioning`; `Comment.timestamp` present (example `4960`), and the guide defines the parameter as "in milliseconds from track start" — [SoundCloud API Explorer](https://developers.soundcloud.com/docs/api/explorer/open-api); [SoundCloud API Guide](https://developers.soundcloud.com/docs/api/guide)
- Yadati, Larson, Liem & Hanjalic (ISMIR 2014, pp. 143–148), "Detecting drops in electronic dance music: Content based approaches to a socially significant music event": 100 SoundCloud tracks (dubstep 36, electro 36, house 28); 190 expert-labelled drops and 225 timed comments containing "drop"; per track roughly 220–278 comments of which 3–5 mention "drop"; "only 20 % of the drop comments in the training set are located at the actual drop in a track"; comments can sit "in neighborhoods far from the actual drop"; content-based detector F1 0.61 at 3 s tolerance rising to 0.71 at 15 s; comment-derived weak labels gave lower F1 than expert labels (attributed to comment noise) — [ISMIR 2014 paper PDF](https://archives.ismir.net/ismir2014/paper/000297.pdf)
- Follow-on: MediaEval 2014 "A Multimodal Approach to Drop Detection in Electronic Dance Music" (Utrecht) and a TU Delft thesis on socially significant music events exist — [Utrecht repository](https://utrecht-main-test.atmire.com/items/2cf889a9-7be7-4a8f-9896-f972ad5e4667); [TU Delft repository](https://repository.tudelft.nl/file/File_53c19119-989c-4ad5-b2d9-fbeec09ed63e) (not read in full)
- ToS: SoundCloud defines User Content to include "comments" and Personal Data to include "any comments or posts by that user"; prohibits scraping and any use "to train or otherwise develop any artificial intelligence technology"; caching only session-based — [SoundCloud API Terms of Use](https://developers.soundcloud.com/docs/api/terms-of-use)

**YouTube comments (Data API v3)**
- `commentThreads.list`: "A call to this method has a quota cost of 1 unit"; `maxResults` 1–100 (default 20); `order` = `time` (default) or `relevance`; `textFormat` = `html` (default) or `plainText` — [commentThreads.list](https://developers.google.com/youtube/v3/docs/commentThreads/list)
- Comment resource: `snippet.textDisplay` — "The comment's text. The text can be retrieved in either plain text or HTML."; `snippet.textOriginal` — "The original, raw text of the comment as it was initially posted or last updated."; `snippet.likeCount` — "The total number of likes (positive ratings) the comment has received."; `snippet.publishedAt` — publication date-time; even plain text may differ from the original (e.g., video links replaced by titles) — [comments resource](https://developers.google.com/youtube/v3/docs/comments)
- Third-party guide: `textDisplay` is HTML "with links wrapped in anchor tags and line breaks encoded as <br>", `textOriginal` is plain text; "Pulling 5,000 comments at 100 per page takes 50+ calls" — [OutlierKit YouTube comments API guide](https://outlierkit.com/resources/youtube-comments-api/)
- Default quota 10,000 units/day (plus 100 `search.list` calls/day), reset at midnight PT — [YouTube quota costs](https://developers.google.com/youtube/v3/determine_quota_cost)
- YouTube API Services Developer Policies: III.E.4.c "After 30 calendar days, the API Client must either delete or refresh the stored data."; III.E.6 clients must not "obtain scraped YouTube data or content."; III.I.14 clients must not "use any technology other than YouTube API Services to access or retrieve API Data."; III.E.4.h clients must not "access or use API Data to create new or derived data or metrics."; III.E.2.a "Do not aggregate API Data except that you may only aggregate API Data relating to YouTube channels." — [YouTube API Services Developer Policies](https://developers.google.com/youtube/terms/developer-policies)
- yt-dlp `--write-comments`: "Retrieve video comments to be placed in the infojson. The comments are fetched even without this option if the extraction is known to be quick" (alias `--get-comments`) — [yt-dlp README](https://github.com/yt-dlp/yt-dlp/blob/master/README.md); fetch-mix-cli fetches "top comments (up to 500)" with yt-dlp and screens them for tracklists — [pkg.go.dev fetch-mix-cli](https://pkg.go.dev/github.com/alexgorbatchev/fetch-mix-cli)

**YouTube "Most Replayed" heatmap**
- yt-dlp info-dict definition (extractor/common.py): "heatmap: A list of dictionaries, with the following entries: 'start_time' - The start time of the data point in seconds; 'end_time' - The end time of the data point in seconds; 'value' - The normalized value of the data point (float between 0 and 1)" — [yt-dlp common.py](https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/yt_dlp/extractor/common.py)
- yt-dlp YouTube extractor `_extract_heatmap` reads `frameworkUpdates.entityBatchUpdate.mutations[].payload.macroMarkersListEntity.markersList` where `markerType == 'MARKER_TYPE_HEATMAP'`, mapping `startMillis`→start_time, `startMillis+durationMillis`→end_time, `intensityScoreNormalized`→value; the extractor's test fixtures expect `'heatmap': 'count:100'` — [yt-dlp youtube/_video.py](https://raw.githubusercontent.com/yt-dlp/yt-dlp/master/yt_dlp/extractor/youtube/_video.py)
- Duico, Strafforello & van Gemert (2023), "Can we predict the Most Replayed data of video streaming platforms?" (arXiv:2309.06102): each video's Most Replayed data is "100 scalars in the [0, 1] range"; dataset YTMR500 (500 CC-licensed vlog/travel videos, 3–20 min, ≥30k views); deep models only slightly beat random at test time (precision@50 ≈56–57% vs 50%); crowd participants did not beat random, inter-rater Krippendorff's α ≈ −0.017; authors suggest multimodal inputs such as audio — [arXiv 2309.06102](https://arxiv.org/abs/2309.06102); data/code — [4TU.ResearchData](https://data.4tu.nl/datasets/0ca18691-3fef-4c9c-9080-12b20daae62a)
- Commercial scrapers of the heatmap exist (e.g., Apify "YouTube Most Replayed Scraper (Heatmap extractor)") — [Apify actor](https://apify.com/karamelo/youtube-most-replayed-scraper-heatmap-extractor?fpr=p2hrc6)
- YouTube Terms of Service (Dated/Effective December 15, 2023): users may not "access, reproduce, download, distribute, transmit, broadcast, display, sell, license, alter, modify or otherwise use any part of the Service or any Content except: (a) as expressly authorized by the Service; or (b) with prior written permission from YouTube and, if applicable, the respective rights holders"; may not "access the Service using any automated means (such as robots, botnets or scrapers) except (a) in the case of public search engines, in accordance with YouTube's robots.txt file; or (b) with YouTube's prior written permission" — [YouTube Terms of Service](https://www.youtube.com/static?template=terms&gl=US)

**Mixcloud**
- No comments endpoint is documented in the Mixcloud API (comments exist only as a rate-limit category) — [Mixcloud developers](https://www.mixcloud.com/developers/)

**Reddit**
- Reddit Data API Terms (Effective June 19, 2023; Last Revised July 20, 2026): "no other rights or licenses are granted or implied, including any right to use User Content for other purposes, such as for training a machine learning or AI model, without the express permission of rightsholders in the applicable User Content." — [Reddit Data API Terms](https://www.redditinc.com/policies/data-api-terms)

### Inferences
- Quota math for ~30,000 YouTube videos: fetching only the first 100 top-level comments per video costs ≥30,000 units → ≥3 days at the 10,000/day default. Boiler Room/Cercle/HÖR videos typically have thousands of comments; at e.g. 2,000 top-level comments (20 pages) per video the cost is ~600,000 units ≈ 60 days, and replies (`comments.list`) add more. A quota increase request or sampling (e.g., `order=relevance`, first 2–5 pages) is needed. (Arithmetic on cited quota figures.)
- Timestamps in YouTube comments are not a structured field: they must be regex-parsed from `textOriginal` (plain "1:23:45") or from anchors in `textDisplay`; the docs read do not document the anchor format, so treat the exact HTML as unverified.
- The YouTube heatmap is the only engagement signal already normalised per video and uniform in resolution (100 bins), making it directly comparable across sets; but per Duico et al. it is a noisy, low-predictability signal, and for a 2-hour set each bin spans ~72 s, coarser than a transition.
- Developer Policy III.E.4.h ("create new or derived data or metrics") and the 30-day refresh rule are in tension with building a persistent research dataset of aggregated reaction metrics from API data; the heatmap itself is not exposed by the Data API at all and is obtainable only via page/InnerTube extraction (yt-dlp), which YouTube's ToS automated-access clause does not authorise.
- SoundCloud's timed comments are the richest per-moment text signal ("ID?", fire emoji, track questions), but the API ToS forbids both retention beyond a session and any AI-training use of User Content; the official API is therefore usable for interactive analysis only, not for building a training set, absent permission.

### Gaps
- No quantitative study of SoundCloud comment *volume* on DJ sets (as opposed to single EDM tracks) was found; Yadati et al. report ~220–278 comments per track for popular singles, not for 1–2 h mixes.
- No research was found that uses YouTube Most Replayed as a music-structure or transition-quality signal; the one study found concerns vlogs.
- YouTube's eligibility threshold for a video to receive a heatmap (view count, age) was not confirmed from a primary source.
- Mixcloud comment data and Reddit timestamped threads were not investigated beyond the ToS/endpoint facts above.
- Whether `textDisplay` encodes timestamps as `<a href="...&t=NNNs">` anchors was not confirmed by Google documentation.

## Key Question 6: Legal/ToS posture summary — scraping vs API, personal non-commercial research

### Takeaway
Of all sources, only MusicBrainz, Discogs (CC0 dumps), AcoustID (non-commercial), and MixesDB (open MediaWiki API with a published crawl-delay) are compatible with a personal research pipeline that stores data; SoundCloud, YouTube, Reddit and Spotify each have written terms that forbid scraping and/or AI-training use or restrict retention, and 1001Tracklists blocks automated access technically without a readable terms page.

### Cited Findings
- SoundCloud API ToS (30 March 2024): bars scraping, bars training AI on User Content (comments included), limits caching to the session; no research exemption — [SoundCloud API Terms of Use](https://developers.soundcloud.com/docs/api/terms-of-use)
- YouTube Developer Policies: 30-day delete/refresh (III.E.4.c), no scraped data (III.E.6), API-only access (III.I.14), no derived data/metrics (III.E.4.h) — [YouTube API Services Developer Policies](https://developers.google.com/youtube/terms/developer-policies); YouTube ToS forbids automated access and downloading except as authorised — [YouTube ToS](https://www.youtube.com/static?template=terms&gl=US)
- Reddit Data API Terms (rev. July 20, 2026): no ML/AI training on User Content without rightsholder permission — [Reddit Data API Terms](https://www.redditinc.com/policies/data-api-terms)
- Spotify: individuals cannot obtain Extended Quota Mode since 15 May 2025; Development Mode requires Premium and is capped at 5 users — [Spotify quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes)
- MusicBrainz: 1 req/s per IP with identifiable User-Agent — [MusicBrainz rate limiting](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting); Discogs: CC0 for monthly dumps and some API data — [Discogs API docs](https://www.discogs.com/developers); AcoustID: "No commercial usage" — [AcoustID](https://acoustid.org/webservice)
- MixesDB: robots.txt `Crawl-delay: 4`, MediaWiki API enabled, no declared content licence (`rightsinfo` empty) — [MixesDB robots.txt](https://www.mixesdb.com/robots.txt); [MixesDB api.php](https://www.mixesdb.com/w/api.php?action=query&meta=siteinfo&siprop=general|statistics|rightsinfo&format=json)
- 1001Tracklists: no terms page found (404), content pages 403 to non-browser clients, curl connections reset — [1001Tracklists](https://www.1001tracklists.com/)
- Raveform (TISMIR 2026) built a published academic dataset from MixesDB metadata and YouTube audio without discussing ToS in the article — [TISMIR 288](https://transactions.ismir.net/articles/288)

### Inferences
- A defensible personal-research stack: MixesDB (tracklists, genre categories, polite crawl) + MusicBrainz/Discogs (release metadata, DJ-mix release groups, CC0 dumps) + AcoustID (identify owned source files) + the researcher's own audio alignment for transition timestamps. Crowd-reaction signals (SoundCloud comments, YouTube heatmaps/comments) are legally the weakest link: usable for exploratory analysis via official APIs, but their ToS do not permit building a retained training corpus, and heatmaps require non-API extraction.
- "Personal, non-commercial" status helps with AcoustID (explicitly allowed) and copyright fair-use arguments but does not create an exemption under SoundCloud, YouTube, or Reddit developer terms, none of which contain a research carve-out in the text read.

### Gaps
- No source addressed US legal treatment (e.g., CFAA/contract) of scraping a site that technically blocks bots but publishes no terms (the 1001Tracklists situation); this is a legal question outside the sources read.
- Discogs API Terms of Use and Beatport ToS could not be read (403 / not fetched), so their retention and research clauses are unquoted.
- MixesDB's own terms/licence page (if any) beyond the empty `rightsinfo` was not located.
